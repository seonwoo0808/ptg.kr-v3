# 프로젝트 방향

이 문서는 프로젝트의 제품 구성과 기술 방향을 정의하는 기준 문서다. 이후 기능을 추가하거나 구조를 변경할 때 아래 원칙을 우선적으로 참고한다.

## 0. 성능
개발자인 나는 Next.js의 느린 성능에 회의감을 느껴 Astro를 선택했고, 웹 페이지 최적화를 통한 빠른 로딩을 기대하고 있다.
이에 부응 할 수 있도록 언제나 성능을 고려한다.
또한, 인간이 직접 수정하는 일이 많으므로 개발자가 만족할 수 있는 재사용성/안정성/시맨틱한 코드로 개발해야 한다.

## 1. 제품 구성

웹사이트는 다음 세 영역으로 구성한다.

### 랜딩

- 방문자가 사이트와 운영자를 빠르게 이해할 수 있는 첫 화면
- 핵심 소개, 전문 분야, 대표 작업, 주요 링크와 연락 방법을 제공
- 포트폴리오와 블로그로 자연스럽게 이동할 수 있는 진입점
- 짧고 명확한 메시지와 시각적 인상을 우선

### 포트폴리오

- 프로젝트와 작업물을 소개하는 공간
- 각 프로젝트의 문제, 역할, 접근 방식, 결과와 사용 기술을 보여줌
- 대표 작업은 요약 카드로 노출하고, 상세 페이지에서 충분한 맥락을 제공
- 작업물의 이미지와 본문이 다양한 화면 크기에서 안정적으로 보이도록 구성

### 블로그

- 기술, 작업 과정, 생각과 기록을 발행하는 공간
- 글 목록, 글 상세, 태그 또는 카테고리 탐색을 지원
- 검색 엔진이 이해하기 쉬운 URL·메타데이터·구조화된 콘텐츠를 고려
- 새 글을 추가하기 쉬운 콘텐츠 중심 구조를 유지

## 2. 다국어 지원

다국어는 초기부터 구조에 반영한다. 특정 언어 하나를 기준으로 나중에 번역을 덧붙이는 방식은 피한다.

- 언어별 URL 규칙을 정의하고 일관되게 유지한다. 예: `/ko/`, `/en/`
- 언어 전환 시 가능한 경우 현재 페이지의 대응 언어 페이지로 이동한다.
- UI 문구와 콘텐츠 번역을 분리해 관리한다.
- 포트폴리오와 블로그 콘텐츠는 언어별 제목, 요약, 본문, 메타데이터를 가질 수 있어야 한다.
- 번역이 없는 콘텐츠의 처리 방식(기본 언어 노출 또는 비노출)을 구현 전에 결정한다.
- 각 언어 페이지에 적절한 `lang`, canonical, alternate 링크와 SEO 메타데이터를 제공한다.

기본 언어와 지원 언어 목록은 콘텐츠 모델을 확정하기 전에 결정한다. 현재 문서에서는 특정 언어를 고정하지 않는다.

## 3. 배포 목표

최종 배포 대상은 Cloudflare의 edge 런타임이다.

- 우선 후보: Cloudflare Pages 또는 Cloudflare Workers
- 정적 콘텐츠와 사전 생성 가능한 페이지는 가능한 한 빌드 시점에 생성한다.
- Workers/Pages 환경에서 동작하지 않는 Node.js 전용 API나 로컬 파일 시스템 의존을 기본 설계에 넣지 않는다.
- 서버 기능이 필요할 경우 Web APIs와 Cloudflare 호환 런타임을 우선한다.
- 환경 변수, 외부 API, 이미지 처리, 폼 제출 등 배포 환경 의존 요소는 로컬과 production에서 동작 방식을 분리해 검증한다.
- 배포 방식은 사이트의 서버 렌더링 필요성, 콘텐츠 업데이트 방식, 외부 서비스 연동 요구를 확인한 뒤 Pages 또는 Workers 중 선택한다.

## 4. 권장 구조

Astro를 기본 프레임워크로 사용하며, 콘텐츠와 화면을 분리한다.

- `src/pages`: 랜딩, 포트폴리오, 블로그와 언어별 라우트
- `src/components`: 여러 영역에서 재사용하는 UI 컴포넌트
- `src/layouts`: 언어·SEO·공통 레이아웃 처리
- `src/content` 또는 이에 준하는 콘텐츠 컬렉션: 포트폴리오와 블로그 원본 콘텐츠
- `src/i18n` 또는 이에 준하는 모듈: 언어 목록, 번역 문구, 언어 전환 로직
- `public`: favicon, 정적 이미지 등 그대로 제공할 자산

실제 디렉터리와 파일명은 구현 단계에서 Astro의 콘텐츠 컬렉션 및 라우팅 방식에 맞춰 조정하되, 영역별 책임은 유지한다.

## 5. 구현 우선순위

1. 공통 레이아웃, 디자인 토큰, 기본 반응형 구조를 정리한다.
2. 언어 목록과 URL 규칙을 확정하고 다국어 라우팅 기반을 만든다.
3. 랜딩 페이지의 핵심 메시지와 포트폴리오 진입 흐름을 구현한다.
4. 포트폴리오 콘텐츠 모델과 상세 페이지를 구현한다.
5. 블로그 콘텐츠 모델, 목록, 상세 페이지를 구현한다.
6. SEO, 접근성, 성능, 이미지 최적화를 점검한다.
7. Cloudflare Pages/Workers 배포 방식을 확정하고 production 환경에서 검증한다.

## 6. 작업 판단 기준

새 기능이나 라이브러리를 도입할 때 다음을 확인한다.

- 세 영역 중 어디에 속하며 다른 영역과 책임이 겹치지 않는가?
- 모든 지원 언어에서 동작할 수 있는가?
- 정적 생성 또는 Cloudflare edge 런타임에서 안정적으로 동작하는가?
- 콘텐츠를 추가·수정하기 쉬운가?
- 접근성, 성능, SEO에 불필요한 부담을 만들지 않는가?

## 7. 추후 확정할 사항

- 기본 언어와 지원 언어
- 언어별 URL 및 번역 fallback 정책
- 포트폴리오와 블로그 콘텐츠 작성·관리 방식
- 이미지 저장 및 최적화 방식
- 문의 폼 또는 외부 서비스 연동 여부
- Cloudflare Pages와 Workers 중 최종 배포 방식
